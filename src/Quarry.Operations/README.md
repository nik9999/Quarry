# Quarry.Operations

Операционный контур, комплаенс, управление бюджетами и миграция данных для RAG-системы **Quarry**.

Модуль реализует эксплуатационные требования промышленного уровня (Production-Grade RAG): миграцию моделей эмбеддингов, соответствие требованиям регуляторов (GDPR, EU AI Act), управление затратами (FinOps / Budget Enforcement) и непрерывный мониторинг качества в реальном времени.

## 1. Миграция и обслуживание данных

### `BackfillScheduler`
Оркестратор обновления эмбеддингов при переходе на новые модели (например, при смене размерности или архитектуры):
* **3 режима выполнения (`BackfillSchedule`)**:
  * `OffPeakNightlyBatch` — быстрое пакетное обновление в ночное окно.
  * `BackgroundTrickle` — непрерывное фоновое обновление с паузами без деградации боевой нагрузки.
  * `ParallelShadowThenCutover` — формирование теневой когорты в изолированном индексе с последующим атомарным переключением.
* **Идемпотентность и отказоустойчивость**: курсор `BackfillProgress` фиксирует завершенные чанки; при прерывании процесс продолжается без повторной обработки. Встроен экспоненциальный retry/backoff при сбоях API эмбеддингов.

### `DriftAdapter`
Математическое выравнивание дрейфа представлений методом **Orthogonal Procrustes**:
* Находит оптимальную матрицу вращения $R$, минимизирующую расстояние Фробениуса $\|A \cdot R - B\|_F$ между старыми и новыми представлениями идентичных текстов.
* Решает задачу через сингулярное разложение ковариационной матрицы ($C = A^T B$, $\text{SVD}(C) = U \Sigma V^T$, $R = U V^T$) с использованием библиотеки `MathNet.Numerics`.
* Позволяет выполнять запросы к старым индексам новой моделью без полного пересчета базы векторов.

### `GdprDeletionPipeline` & `MinHashDeduplicator`
* **GDPR Article 17 ("Право на забвение")**: жесткое удаление (Hard Delete, а не tombstone) векторов из `IVectorStore` и сущностей из графа знаний с формированием юридически заверенной записи `DeletionAuditEntry`.
* **MinHash / LSH дедупликация**: вычисление $k$-перестановочных сигнатур МинХэша по 1-шинглам слов для группировки и фильтрации семантических дубликатов на основе коэффициента Жаккара.

## 2. Комплаенс и регулирование ИИ (EU AI Act & GDPR)

### `CitationAuditor`
* Прослеживает исторический ответ по его `QueryId` через таблицу аудита `AuditEntry`.
* Извлекает процитированные чанки и повторно вычисляет HMAC-SHA256 сигнатуру происхождения (`IProvenanceSigner`).
* Обнаруживает искажения или подмену текста первоисточника между моментом индексации и моментом аудита (`SignatureValid = false`).

### `ComplianceDashboard` & `ConsentRegistry`
* **Дашборд**: агрегирует 6 ключевых показателей надежности:
  1. *Faithfulness (today)* — суточная достоверность генерации.
  2. *PII redaction rate* — доля обезличенных персональных данных.
  3. *Tenant leaks prevented* — количество предотвращенных межтенантных утечек.
  4. *Active erasure requests* — статус открытых заявок на удаление данных.
  5. *Consent coverage* — процент покрытия активными согласиями пользователей.
  6. *Open incidents* — число открытых инцидентов регуляторного риска.
* **Реестр согласий**: поддерживает независимый отзыв согласий для конкретных целей (например, отзыв согласия на `analytics` при сохранении `core-search`).

### `ExplanationPanel`, `HumanReviewQueue` & `ErasureReceipt`
* **Объяснимость**: для систем с ограниченным риском (`Limited`) отображаются краткие чипы (уверенность, число источников, модель); для высокого риска (`High`) формируется полный аудит-трейс с отображением шагов рассуждения и кнопкой эскалации человеку.
* **Human-in-the-loop**: очередь ручной проверки сомнительных или низкодостоверных ответов экспертами. Результаты правок (`ReviewerEdit`) накапливаются как золотой тестовый набор (Golden Evaluation Cases).
* **Квитанция об удалении**: формирует JSON-документ `ErasureReceipt` с детальным отчетом по затронутым хранилищам, проверкой SLA (30 календарных дней) и открепленной HMAC-подписью.

## 3. Управление бюджетами и защита от перерасхода (FinOps)

### `BudgetEnforcingPipeline`
В отличие от пассивных метрик, данный декоратор является **активным защитным барьером**:
1. **Pre-execution проверка**: решение о допуске запроса принимается **до** обращения к LLM. Если тенант исчерпал лимит, токены не тратятся.
2. **Три эшелона защиты**:
   * **Spend Quota**: ограничение суммарных затрат в долларах за скользящее окно (по умолчанию $5/час).
   * **Rate Ceiling**: ограничение частоты запросов (`RateLimiter`) для предотвращения спама и зондирования квот.
   * **Circuit Breaker**: при превышении квоты предохранитель размыкается на заданный период (`BreakerCooldown`, например 5 минут), мгновенно отклоняя последующие вызовы без повторного сканирования леджера.
3. **Обработка отказа**: генерируется исключение `BudgetExceededException` с указанием тенанта и причины (`SpendQuotaExceeded`, `RateLimitExceeded`, `CircuitOpen`), транслируемое хостом в HTTP 429 Too Many Requests.
4. **Потоковая передача**: проверка выполняется до открытия SSE-потока, а окончательная стоимость сгенерированного ответа списывается с баланса тенанта по завершении генерации.

## Регистрация в DI

```csharp
// Регистрация в контейнере зависимостей
services.AddBudgetEnforcement(
    policy: new BudgetPolicy(
        SpendQuotaUsd: 10.0,
        MaxRequests: 100,
        RateWindow: TimeSpan.FromMinutes(1),
        BreakerCooldown: TimeSpan.FromMinutes(10)),
    window: TimeSpan.FromHours(1),
    tenantAccessor: () => httpContextAccessor.HttpContext?.User?.FindFirst("tenant_id")?.Value ?? "default"
);
```
